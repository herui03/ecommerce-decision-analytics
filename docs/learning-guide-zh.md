# 学习指南：核心概念与亲手复现练习（中文）

这份指南面向想看懂或复现这个项目的读者：先用「字面拆解 → 场景重演 → 简单版 / 进阶版」理解 7 个核心概念，再做几个 30 分钟内能完成的复现练习。练习里的每个数字都能用本仓库的文件自己算出来。

> 数据说明：市场数据来自公开的 Brazilian E-Commerce Public Dataset by Olist 与 Marketing Funnel by Olist（CC BY-NC-SA 4.0），广告实验只用到 Criteo Uplift Modeling Dataset 的六个汇总计数。历史数字来自仓库里保留的早期全量运行产物，在这里重算过，但没有重跑。

## 1. 七个核心概念

### 1.1 加权比率 vs 比率的平均（分母问题）

- **字面拆解**：「迟到率」是一个**比率**，分子是迟到订单数（一个计数），分母是**已送达**订单数（另一个计数）。「加权」的意思是：先把 20 个月的分子全加起来，再把分母全加起来，最后相除一次。
- **场景重演**：你在 Excel 里有 20 行月度数据，每行一个迟到率。你顺手在底部写 `=AVERAGE(C2:C21)`，得到 5.89%。另起一格写 `=SUM(迟到)/SUM(已送达)`，得到 6.79%。两个数差了 0.9 个百分点，而这份表格不会报任何错。
- **简单版**：两家分店，A 店 100 单迟到 50 单，B 店 900 单迟到 0 单。两店迟到率的平均数是 25%，但公司整体只迟到了 5%。只有「总迟到 ÷ 总单数」才是公司的真实迟到率。
- **进阶版**：比率的平均数，等于给每个分组相同的权重（1/n）；加权比率给的是分母占比的权重。当分母差异大（2017-01 只有 750 单送达，2017-11 有 7,289 单），而且比率和分母相关时，两者会系统性地偏离。坑：①分母必须是比率**真正**除过的那个数：迟到率除以「已送达」，不是「全部订单」；②平均值类指标（平均送达天数）的分母是「非空值的个数」，历史 extract 没存这个数，所以跨月合并只能标「不可用」，不能拿已送达订单数去加权。

### 1.2 粒度（grain）与扇出（fan-out）

- **字面拆解**：「粒度」是一张表里一行代表什么：一单？一件商品？一次付款？「扇出」是指用非唯一的键做 JOIN，行数被乘开了。
- **场景重演**：订单表 1 行 1 单，商品表 1 单可能有 3 行，付款表 1 单可能有 2 行。你一次 JOIN 三张表，这一单就变成 3×2=6 行，付款金额被加了 3 次。历史测量：付款多出 26%（+4,179,056.58 BRL），同时有 1,525 单因为 INNER JOIN 而消失。
- **简单版**：一张小票钉着 3 道菜和 2 张卡，按「纸张」而不是按「小票」数钱，就会把钱数重复。
- **进阶版**：修复办法是先把每个子表聚合到订单粒度，再用 LEFT JOIN 挂到订单主表上，最后断言「行数 = 订单数」「金额 = 源头金额（精确到分）」。本项目用 6 个变异测试证明这些断言真的会失败，比如把 LEFT 改成 INNER JOIN 会被 `equal_rowcount` 抓住。坑：品类（category）是**商品粒度**的属性，727 单跨多个品类，所以「按品类的订单数」跨品类相加会重复计算。

### 1.3 ITT（意向处理效应）

- **字面拆解**：Intention-To-Treat，「按分配分组」。比较的是**被分到**实验组的人和被分到对照组的人，不管他们实际有没有看到广告。
- **场景重演**：这个广告实验随机把 85% 的用户放进实验组，但实验组里只有 3.6% 真的看到了广告。ITT 比较的是全体实验组（0.3089%）和全体对照组（0.1938%）的转化率，差 +0.1152 个百分点，95% CI [+0.1085, +0.1219]。
- **简单版**：你能买的是「给这群人投放」，不是「让这群人看到」。所以衡量「投放这个决定」值不值，要看 ITT。
- **进阶版**：只有随机化本身被用上时，ITT 才能被识别，不需要额外假设（SUTVA 除外）。坑：①不能用「看到广告的人 vs 对照组」（+2,675.83%），曝光是用户自己的浏览行为选出来的，属于选择偏差；②n=1398 万时 p≈10^-178，显著性几乎不提供信息，要看区间大小和经济性。

### 1.4 CACE（依从者平均因果效应）

- **字面拆解**：Complier Average Causal Effect，只针对「如果被分到实验组就会看到广告」的那部分人（依从者）的效应。计算方法：ITT ÷ 依从率 = 0.1152 ÷ 0.036037 = +3.1964 个百分点。
- **场景重演**：把 ITT 看成被 96.4% 从未曝光的人「稀释」过的效应，CACE 就是把稀释去掉，回答「对真正看到广告的那类人，效果多大」。
- **简单版**：广告创意对「会看到它的人」很有效；但你没法只买这群人。
- **进阶版**：需要排他性约束（分配只能通过曝光影响转化，无法检验）和单调性（对照组不可能被曝光，本数据成立）。依从者和其他人差别很大（历史 SMD 0.85），所以 CACE 不能推广到全体。本项目用 Wald 估计量和「依从者分解」两种代数独立的方法算 CACE，两者一致，并用含协方差的 delta 方法给出区间。

### 1.5 标签成熟度（as-of 截止与净化间隔）

- **字面拆解**：「90 天内成交」这个标签，要等 90 天窗口**结束**后才知道答案。「as-of」是模型上线那一刻（当天 00:00），只有那之前已经完整知道的标签才能拿来训练。
- **场景重演**：1 月 1 日来的线索，窗口是 1 月 1 日到 4 月 1 日（含首尾），要到 4 月 2 日 00:00 才完整。历史模型在 4 月 1 日切分，却用了 1–3 月线索的完整标签，而这些窗口在 4 月 1 日到 6 月 29 日之间才结束。**切分那一刻，没有一个训练标签是完整的。**
- **简单版**：你不能在考试当天，用还没批完的卷子来训练「谁会考好」的模型。
- **进阶版**：修正后的设计声明 `train_end = as_of − 91 天`（净化间隔 = 窗口 + 1 天）、评分队列和「结果观测截止日」（这是一个**假设**：数据没有说明观测截止日，最晚一次成交日期不能证明所有负样本都被完整跟踪了）。按真实日期，as-of 2018-05-01 只能用 1 月 1–30 日的线索训练，训练集小得多。这是诚实的代价。

### 1.6 前瞻泄漏（point-in-time 特征）

- **字面拆解**：一个特征如果用到了「预测那一刻还不存在的信息」，就是前瞻泄漏，即使它不碰标签。
- **场景重演**：`page_lead_volume` 数的是整个数据集里同一落地页的线索数，包括未来到来的和测试期的线索。修正版 `page_lead_volume_prior` 只数**严格更早**的线索；测试会删掉、复制、改写所有未来行，断言早期特征一个都不变，并且证明旧特征**会**变（说明这个测试真的抓得到泄漏）。
- **简单版**：用「这家店以后会有多火」来预测「今天进店的客人会不会买」。
- **进阶版**：泄漏不一定抬高测试分数。在合成数据上，旧特征让 LR 的 AUC 略降、GB 的 AUC 上升。缺陷在于它上线时根本算不出来，而不是「保证会虚高」。同日线索也被排除，因为源数据没有日内时间戳。

### 1.7 并列（ties）与 tie-aware top-k

- **字面拆解**：多个线索得分完全相同，就是「并列」。选前 k 名时，截断点正好落在并列块中间，选谁进来就取决于排序方式。
- **场景重演**：LR 在第 265 名的位置有 7 个同分线索，其中 2 个成交了。根据行顺序不同，命中数可能是 52、53 或 54；对所有排列取平均是 52.86。常数基线让所有线索都并列，历史报告的 9.43% 只是 argsort 恰好先挑到的那 265 行，正确期望是基准率 10.55%。
- **简单版**：同分的人谁排前面是抽签，把抽签结果当成模型的本事就不对了。
- **进阶版**：导出时用（得分降序，线索 ID 升序）保证确定性；报告时给出 tie-aware 期望值和 min–max 区间；另外用置换不变性测试证明，打乱输入行后输出完全一样。

## 2. 亲手复现练习（每个 ≤ 30 分钟）

建议先完成 1、2、3。每个练习都能在本机看到结果。

1. **加权 vs 平均（10 分钟）**：用 Excel 或 pandas 打开 `tableau/extracts/mart_monthly_performance.csv`，分别算 `SUM(late_orders)/SUM(delivered_orders)` 和 `AVERAGE(late_delivery_rate_pct)`。结果应为 6.7892% 和 5.8874%。
2. **并列的 top-k（20 分钟）**：打开 `outputs/lead_scores_test.csv`，按 `score_lr` 降序排，找到第 265 名的分数，数一数同分的有几行、其中几个 `is_won_90d=1`。应该是 7 行同分、2 个成交，命中范围 52–54。
3. **标签成熟日期（5 分钟）**：手算 2018-01-01 + 90 天 = 2018-04-01（窗口结束日），可用日是 04-02；2018-03-31 + 90 天 = 2018-06-29。解释为什么 2018-04-01 切分时没有一个训练标签是完整的。
4. **ITT 置信区间（15 分钟）**：用 36,711/11,882,655 和 4,063/2,096,937 按 Wald 公式算差值和 95% CI，应为 +0.1152pp [+0.1085, +0.1219]。
5. **跑一遍管道（15 分钟，需要 Python 3.11/3.12）**：`scripts/setup.sh && make sample && git status`，确认输出和提交的一模一样；再故意把 `int_orders__enriched.sql` 里的 `left join items` 改成 `join items`，跑 `make sample`，看 dbt 哪个测试失败，然后改回来。

## 3. 术语表

| 术语 | 一句话人话解释 | 现在需不需要懂 |
|---|---|---|
| 粒度 grain | 一行数据代表什么（一单、一件商品） | 需要 |
| 扇出 fan-out | JOIN 时一行变多行，金额被重复加 | 需要 |
| 加权比率 | 先分别加总分子分母，再相除 | 需要 |
| 有效值个数 valid count | 平均值真正除以的那个数（非空值的个数） | 需要 |
| ITT | 按「被分配到哪组」比较的效应 | 需要 |
| CACE / LATE | 只对依从者的效应，需要额外假设 | 需要 |
| 排他性约束 | 分配只能通过曝光影响结果（无法检验） | 了解即可 |
| SMD | 标准化均值差，衡量两组是否平衡（<0.1 通常视为平衡） | 了解即可 |
| MDE | 实验设计能可靠检测到的最小效应 | 需要 |
| 标签成熟 / as-of | 标签在观测窗口结束后才可用；上线时刻之前可用的才能训练 | 需要 |
| 净化间隔 purge gap | 训练集结束和上线之间留出的空档，这里是 91 天 | 需要 |
| 前瞻泄漏 look-ahead | 特征用到了预测时还不存在的信息 | 需要 |
| point-in-time 特征 | 只用预测时刻之前的信息算出的特征 | 需要 |
| tie-aware top-k | 截断点落在并列块中时，对所有排列取期望 | 需要 |
| 变异测试 mutation test | 故意改坏代码，看测试会不会失败 | 需要 |
| 确定性 determinism | 同样的输入每次得到字节级相同的输出 | 了解即可 |
| CSP | 浏览器安全策略；本页禁止任何网络请求 | 了解即可 |
| CC BY-NC-SA 4.0 | 署名、非商业、相同方式共享的数据许可 | 需要（数据使用边界） |
